## Final worker/Celery configuration

`compose.yaml` worker command:

```
celery -A app.workers.celery_app:celery_app worker --pool=solo
  --loglevel=INFO --concurrency=1 --max-tasks-per-child=1
  --queues=media,transcription
```

- `--pool=solo` is required: pre-fork pool processes are daemonic and cannot
  spawn the Whisper child (`multiprocessing` asserts "daemonic processes are not
  allowed to have children").
- `PYTHONPATH=/app` is set on the worker: the image `pip install .` also places a
  stale copy in site-packages that shadows the mounted source; spawned children
  must resolve `app` from the mount.
- `celery_app.py` sets `worker_concurrency=1`, `worker_prefetch_multiplier=1`,
  `worker_max_tasks_per_child=1`.

## Whisper subprocess lifecycle guarantee

- `WhisperEngine.transcribe` runs the native model in a spawned child
  (`app/runtime/model_process.py`, multiprocessing `spawn`).
- The child loads the model, transcribes, fully consumes generators, drops
  references, runs `gc.collect`, and returns a bounded picklable envelope
  including the child's peak RSS.
- The parent monitors queue data and process liveness together: a child killed by
  SIGKILL/OOM/segfault without an envelope is reaped within ~0.25 s instead of
  the 7,200 s timeout.
- The parent `join()`s/reaps the child and verifies a non-live exit state before
  the heavy-model lease is released.

## Redis lease and unsafe-unload guarantee

- One key `clipfactory:heavy-model`; `SET NX PX` acquire, ownership-checked Lua
  renew, atomic compare-and-delete release. `HeavyModelLeaseBusy.retryable=True`.
- `renew()` treats a Redis exception or Lua return 0 as ownership loss
  (`ownership_lost=True`); the renewer stops, and the executor raises a retryable
  error so the stage fails closed instead of running a second heavy model
  concurrently.
- On an unload warning, `lease.retain()` keeps the key renewing indefinitely:
  new heavy-model acquisition is blocked until the operator runs
  `lease.clear_retained()` after confirming `ollama ps` shows the model absent.
- Ollama unload sends `{"model": ..., "keep_alive": 0, "stream": false}` then
  polls `/api/ps` until the model disappears or a bounded timeout records an
  `unload_outcome` warning.
